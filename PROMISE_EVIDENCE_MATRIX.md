# Promise → Implementation → Evidence

Phase 3 of the trust campaign re-read every substantive public claim in the
legal pages, the landing page, the documentation, SECURITY.md and
security.txt, and checked each against the code that would implement or
contradict it. **130 claims** were assessed.

| Verdict | Meaning | Count |
|---|---|---|
| TRUE | The code does what the claim says, and a test pins it | 70 |
| TRUE_UNTESTED | The code does what the claim says; no test pins it | 11 |
| NOT_VERIFIABLE | An operational or organizational promise the codebase cannot prove | 12 |
| MISLEADING | Technically defensible, but a reader would be misled | 29 |
| FALSE | The code contradicts the claim | 8 |

The eight FALSE findings and the most load-bearing MISLEADING ones were
corrected in this pass — three by changing the CODE (receipts kept memory
labels through an erasure that promised none; a test named for SECURITY.md
never opened it; stored exports kept serving deleted content), the rest by
correcting the sentence to describe what the system actually does. Everything
still marked MISLEADING below is recorded deliberately: it is either owner
copy that needs a product decision, or wording that wants professional review
rather than an engineer's rewrite. Nothing here has been quietly dropped.

Verdicts are ordered worst-first.
